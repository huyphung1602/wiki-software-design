# Tactical Tornado

The tactical tornado is Ousterhout's archetype for the extreme [[tactical-programming|tactical]] programmer: a prolific developer who pumps out code far faster than others but works in a totally tactical fashion. When it comes to implementing a quick feature, nobody gets it done faster.

In some organizations, management treats tactical tornadoes as heroes. However, they leave behind a wake of destruction — their code is rarely celebrated by the engineers who must work with it later. Other engineers must clean up the messes, which makes the real heroes (the cleanup crew) appear slower than the tornado.

The tactical tornado pattern illustrates a broader organizational trap: **optimizing for short-term output metrics** (features shipped, commits per week) rather than long-term system health. What looks like productivity is actually [[technical-debt|debt creation]].
