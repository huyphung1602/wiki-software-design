# Programming as Theory Building

"Programming as Theory Building" (1985) by Peter Naur is one of the most cited essays on the nature of programming. Naur argues that the dominant view of programming as text production is fundamentally misleading — the primary result of programming is not the program text but the theory that programmers build of how the program maps to the real world.

The Theory Building View has profound practical implications. Documentation is secondary and auxiliary — it can jog memories and set up pathways of thought, but the theory itself cannot be expressed in writing, only held by people. Program modifications require the programmer to perceive similarity between new demands and existing capabilities — a judgment that cannot be reduced to rules. When teams lose the theory (program death), attempts to revive it from documentation alone are at best costly and at worst impossible; the better path is often to discard the code and solve the problem fresh.

Naur's view challenges conventional assumptions about programming method, programmer status, and software economics. It resonates with discussions of [[tacit-knowledge]], [[continuous-design]], and the limits of formal documentation.
